# Metodología

Este documento es el contrato del curso. Si una lección lo incumple, la lección está mal.

## Principio rector

La prioridad es aprender bien, no terminar rápido. Memorizar una definición no es saber aplicar un concepto, y aquí solo cuenta lo segundo.

## Orden de aprendizaje

El curso tiene tres rutas (Java, Angular, React y Next.js). En todas, la progresión es obligatoria y va de abajo hacia arriba. Esta es la de la ruta Java, la más extensa; las de frontend siguen el mismo orden de ideas con su tecnología:

1. Fundamentos de programación y orientación a objetos.
2. Principios SOLID.
3. Patrones de diseño.
4. Clean Code, refactorización y testing.
5. Arquitectura de software.
6. Java avanzado, Spring Boot avanzado, bases de datos, sistemas distribuidos, Cloud, System Design y liderazgo técnico.

No se salta a temas avanzados. Un patrón de arquitectura explicado a alguien que no distingue acoplamiento de cohesión es decoración.

## El ciclo de nueve pasos

Cada concepto se enseña así:

| Paso | Qué ocurre |
|---|---|
| 1. Explicación para principiantes | Palabras sencillas y una analogía, como si fuera la primera vez. |
| 2. Explicación técnica | El mismo concepto con la terminología correcta de ingeniería de software. |
| 3. Código incorrecto | Un ejemplo en Java que funciona pero tiene problemas de diseño. |
| 4. Análisis | Cómo identificar el problema y qué consecuencias tiene. |
| 5. Código mejorado | La refactorización paso a paso y por qué es mejor. |
| 6. Taller práctico | Un ejercicio para aplicar el concepto sin ayuda. |
| 7. Revisión técnica | Evaluación de la entrega: deficiencias, riesgos y oportunidades de mejora. |
| 8. Aplicación profesional | Cómo aparece el concepto en proyectos reales con Java y Spring Boot. |
| 9. Evaluación senior | Preguntas de análisis y diseño que exigen justificar decisiones. |

## Qué incluye cada principio SOLID

1. Explicación sencilla con una analogía cotidiana.
2. Definición técnica.
3. Ejemplo en Java que viola el principio.
4. Por qué ese código es un problema.
5. Refactorización paso a paso.
6. Ejemplo empresarial con Spring Boot.
7. Taller práctico sin solución inicial.
8. Preguntas de entrevista senior.
9. Situaciones en las que aplicar el principio produce complejidad innecesaria.

## Qué incluye cada patrón de diseño

El objetivo no es memorizar patrones sino reconocer los problemas que los justifican.

- Qué problema resuelve.
- Cómo reconocer cuándo usarlo.
- Qué alternativas existen.
- Código Java antes y después.
- Cómo aparece en Spring Framework.
- Ventajas, desventajas y trade-offs.
- Errores comunes.
- Taller práctico.
- Cuándo no conviene implementarlo.

Se profundiza primero en los patrones más usados en aplicaciones empresariales Java.

## Reglas

- No se presupone ningún conocimiento que no se haya demostrado.
- No se entrega la solución de un taller antes de que exista un intento.
- En la ruta Java, Java es el lenguaje principal y Spring Boot entra cuando los fundamentos están claros. En las rutas de frontend, TypeScript va antes que el framework.
- Los ejemplos son progresivos: de clases sencillas a sistemas empresariales.
- Toda decisión técnica se explica con sus razones.
- SOLID y los patrones no son reglas absolutas. Cada lección dice cuándo no aplicarlos.
- Una respuesta incorrecta se explica y se da la oportunidad de corregirla.
- No se avanza de módulo sin comprobar que los conceptos fundamentales quedaron entendidos.

## Ritmo

Cualquier cronograma es una planificación inicial flexible, no una fecha límite. Si SOLID, los patrones o la arquitectura necesitan más tiempo, el cronograma se ajusta.

## Objetivo final

Pasar de entender los fundamentos a diseñar, implementar, probar, optimizar y defender soluciones con criterio de ingeniería senior.
