# TDD: desarrollo guiado por pruebas

Cuatro talleres, en orden. Requisito: saber escribir una prueba con JUnit ([Nivel 4 de Java](../../java/nivel-04-clean-code-testing/)) o con el marco de pruebas de tu lenguaje.

| # | Sesión | Taller |
|---|---|---|
| 01 | [Rojo, verde, refactor](01-rojo-verde-refactor/) | Una kata completa, con el ciclo registrado commit a commit |
| 02 | [De afuera hacia adentro, y los dobles de prueba](02-de-afuera-hacia-adentro/) | Un caso de uso que descubre sus puertos con las pruebas |
| 03 | [TDD sobre código heredado](03-codigo-heredado/) | Caracterizar, refactorizar y ampliar un código sin pruebas |
| 04 | [Los límites de TDD y la calidad de las pruebas](04-limites-y-calidad-de-las-pruebas/) | Pruebas de mutación, propiedades y una política de pruebas |

Los ejemplos se ejecutan con `java Main.java`. Traen un ejecutor de pruebas mínimo dentro del propio archivo para no depender de nada; en los talleres se usa un marco de pruebas de verdad.
